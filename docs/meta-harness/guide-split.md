# G4 proposal: one guide for every project, rules per project

Status: proposal for the user's approval (2026-11-10). Nothing is moved yet. Part of the global install
([global-install.md](global-install.md) §3, §5, §6).

Today `templates/AGENTS.md` (~4,000 words) is filled in per workspace by setup: placeholders (`{{NAME}}`,
`{{REPO_ROWS}}`, `{{REPO_SECTIONS}}`, `{{DEV_ROWS}}`, `{{ROOT}}`…) and `TODO(orchestrator-setup)` sections, then
edited by the user. With the global install the common part lives once in the clone, and what belongs to one
project lives under `~/.hat/projects/<id>/`.

## 1. Where each section goes

| Section today (words) | Goes to | Notes |
|---|---|---|
| Layout (93) | **common** rule + **project** table | Common: "read the repo's guide before changing it; git inside the repo; one PR per repo". Project: the repos, base branches and guide paths, from `config` (`REPOS`, `BASE_<repo>`), shown at session start |
| Commands (16) | **project** `rules.md` | per repo: run, test, single test, lint, format, typecheck |
| Repo guides (26) | **project** `rules.md` | only for repos without their own `CLAUDE.md`/`AGENTS.md` |
| How the repos connect (28) | **project** `rules.md` | contracts and cross-repo decisions |
| Standards (129) | **common** defaults + **project** choice | the default table stays common; `config` › `STANDARDS` lists which apply; a project's own standard is a skill in its repo, named in `rules.md` |
| Orchestrator role (130) + flow, outcome, briefs (≈ 2,100) | **common** | paths become the project's state dir (§3) |
| Session memory | **common** | `memory/` → `<state>/memory/`; sync-memory commits in `~/.hat` (G-D2) |
| Token budget (716) | **common** | model names per tier stay in `config` |
| Workspace rules (73) | **project** `rules.md` › *Rules* | the user's lasting corrections still land here, now outside the repo |
| Git (234) | **common** | conventions stay per repo (its guide or `rules.md`); `GIT_WRAPPER`, `ATTRIBUTION` in `config` |
| Tool mapping (400) | **common**, rewritten | `~/.claude/settings.json`, `~/.claude/agents/`, `~/.claude/skills/` instead of the project's `.claude/` |

About 90 % of the text is common. A project's `rules.md` starts with Commands, Repo guides, How the repos connect
and Rules, filled by `hat project add` from what setup detects today, and left as `TODO` where it can't.

## 2. Agents

| Today | Becomes |
|---|---|
| `explorer`, `architect` per workspace | `hat-explorer`, `hat-architect` in `~/.claude/agents/` (the prefix avoids clashing with the user's own agents) |
| one `<repo>-dev` per repo, with `{{REPO}}`, `{{ROOT}}`, stack and a standards digest baked in | one `hat-dev`. The brief gives the repo path, its guide, its commands (from `rules.md`) and the standards that apply. The default digest stays in the agent; a project's different standard reaches it through the brief |
| Codex `.codex/agents/*.toml` | the same three in `~/.codex/agents/`, generated by `agent-to-codex.py` |

Model tiers are unchanged: the orchestrator picks the model per brief.

## 3. How a session finds its project

The SessionStart hook (G2) prints, for a registered project only:

```
hat project <id> · root <root> · state ~/.hat/projects/<id>
Guide: <clone>/guide/AGENTS.md (read it before anything else) · Project rules: <state>/rules.md
<memory: NEXT_STEPS, PROJECT_STATE> · <decision index> · <handoff draft, if any>
```

The guide writes `<state>` for the state dir and `<root>` for the project root; the orchestrator reads them from
this header. Reading the guide costs what the `CLAUDE.md` import costs today (once per session, cached after).

**Limit to check in G2.** G0 measured ~9.3k characters of SessionStart context per hook. Memory (≤ 1,200 words,
~8k characters) and the decision index (~6k on a large project) are two hooks today. If the limit is per hook,
nothing changes; if it is per session, the decision index moves to a file the guide points to.

## 4. Skills and checklist

- `sync-memory`, `pre-pr-review`, `orchestrator-metrics`, `software-principles`, `design-patterns`: one copy in
  the clone, linked into `~/.claude/skills/` and `~/.agents/skills/` by `install.sh --global`. They take the
  state dir from `hat resolve`. A repo's own copy of a standard still wins.
- `pre-pr-checklist.md`: the default in the clone; `<state>/checklist.md` replaces it for a project that has its
  own. Items are cited by title, not number (G5).

## 5. What stays the same

The flow (Organic + Outcome-driven), sizes, tiers, TDD, the pre-PR gate, the run log, memory rules, push and
merge rules. G4 moves text and removes placeholders; it changes no rule.

## 6. Decisions for the user

| # | Question | Recommendation |
|---|---|---|
| G4-D1 | Agent names | `hat-explorer`, `hat-architect`, `hat-dev` |
| G4-D2 | One `hat-dev` for every repo, briefed per repo, instead of one agent per repo | yes: per-repo agents can't be global, and the brief already carries repo, criteria and contract |
| G4-D3 | Where the common guide lives | `<clone>/guide/AGENTS.md`, read through the SessionStart header (not `~/.claude/CLAUDE.md`, which every session on the machine would load) |
